# Materialize 3D 0.3.0

Source release notes. Version 0.3.0 replaces the 0.2.2 app with a chat studio. You describe an object, an agent makes it, and the chat ends in a 3MF for a Bambu Lab P2S. The old sign, part, printer, and MakerWorld screens are gone. The [Releases page](https://github.com/AojdevStudio/materialize-3d/releases) reports distribution status.

## Before you update

0.3.0 is a different app with the same name. Read [What left the app](#what-left-the-app) first.

- On 0.2.2, the app offers 0.3.0 at launch. **Update now** installs it. **Later** keeps 0.2.2 and asks again at the next launch.
- On 0.2.1 or older, install 0.3.0 by hand from its DMG.
- Your 0.2.2 data stays on disk, but 0.3.0 does not show it. [Your data](#your-data) says where it is.
- Your 0.2.2 API key is not carried over. Sign in again in 0.3.0.

## The app is a chat studio

Since 0.2.2, the app became a window around one loop: a chat with an agent that ends in a print file ([#191](https://github.com/AojdevStudio/materialize-3d/pull/191)).

- **One folder per project.** The agent works in `~/Documents/Materialize 3D/<date>-<slug>/`. It writes parameters, models, checks, an assembly guide, and a sliced 3MF there.
- **Your own sign-in.** The agent runs on your Claude, ChatGPT, or OpenCode Go account, by subscription or by API key ([#199](https://github.com/AojdevStudio/materialize-3d/pull/199)). The sign-in lives in the macOS Keychain, never in a file or a log. Your provider's plan or API charges apply.
- **The app's own tools.** The agent reads and writes files only in the project folder, runs its scripts with uv, slices with Bambu Studio, and can hand a step to GPT 6 Astra on your ChatGPT sign-in ([#194](https://github.com/AojdevStudio/materialize-3d/pull/194), [#200](https://github.com/AojdevStudio/materialize-3d/pull/200)). It does not load your own coding agent setup.
- **Nothing lost on a quit.** A signed helper process, the sidecar, keeps every chat in one store ([#197](https://github.com/AojdevStudio/materialize-3d/pull/197), [#198](https://github.com/AojdevStudio/materialize-3d/pull/198)). A turn that a quit, a crash, or an update cut off goes on from its last finished step. A finished step does not run twice ([#200](https://github.com/AojdevStudio/materialize-3d/pull/200), [#201](https://github.com/AojdevStudio/materialize-3d/pull/201)).
- **It names what is missing.** Send stays off until a sign-in, a model, uv, and Python are there, and a notice names the fix. A turn that needs a sign-in waits with the fix named, then goes on ([#201](https://github.com/AojdevStudio/materialize-3d/pull/201)).
- **Updates wait for the agent.** **Update now** waits until no agent work runs, then installs and restarts ([#201](https://github.com/AojdevStudio/materialize-3d/pull/201)).
- **Slicing.** The agent slices with Bambu Studio 02.08.02.61 and the P2S 0.4 mm presets ([#197](https://github.com/AojdevStudio/materialize-3d/pull/197)). If macOS holds Bambu Studio's launch, the version check stops after 15 seconds with an error that says how to recover ([#230](https://github.com/AojdevStudio/materialize-3d/pull/230)).
- **You print from Bambu Studio.** **Open in Bambu Studio** opens the 3MF. Check it there and print from there. The app does not send jobs to a printer.

## The new studio look

This release also gives the studio its own design.

- **Icon and logo.** The wireframe cube is the app icon, the window icon, and the sidebar logo ([#232](https://github.com/AojdevStudio/materialize-3d/pull/232)).
- **Light and dark.** A light theme with the Inter font, and a true-black dark theme. The toggle is at the bottom of the sidebar, and the app keeps your choice ([#235](https://github.com/AojdevStudio/materialize-3d/pull/235)).
- **Sidebar by status.** Projects group into Working, Ready to print, Printed, and Drafts. A row menu marks a project printed ([#237](https://github.com/AojdevStudio/materialize-3d/pull/237)). Clicking the open project again keeps its files and preview ([#229](https://github.com/AojdevStudio/materialize-3d/pull/229)).
- **Start screen.** "What are we making?" with four suggestions and your recent projects. **Attach** takes any file. A picture goes to the model as a picture. Any other file goes into the project's `refs/` folder, and the message names its path. A model picker sets the model for each project ([#238](https://github.com/AojdevStudio/materialize-3d/pull/238)).
- **Chat.** A turn's tool steps fold into one run trace with a timer and a step count. Replies show as formatted text, with headings, lists, and tables ([#240](https://github.com/AojdevStudio/materialize-3d/pull/240)).
- **Right panel.** Tabs for Guide, Model, Drawing, and Files, with the guide first. **Pop out** opens a view in its own window. A print files bar shows how many 3MFs are ready, with **Reveal** and **Open in Bambu Studio**. The 3D view follows the theme ([#244](https://github.com/AojdevStudio/materialize-3d/pull/244)).
- **Guides match the app.** The agent fills one guide template that uses the app's font and colors and follows the light or dark theme. A toggle keeps the guide on its step ([#247](https://github.com/AojdevStudio/materialize-3d/pull/247)).

## What left the app

These parts of 0.2.2 are gone. A 0.2.2 user loses them on update.

- **The old screens** ([#191](https://github.com/AojdevStudio/materialize-3d/pull/191), [#216](https://github.com/AojdevStudio/materialize-3d/pull/216)): the sign and part views, revision history, approval, Save export, Model Library, the MakerWorld browser, Settings with its About section, and the code editor.
- **The old assistant and the MCP server** ([#219](https://github.com/AojdevStudio/materialize-3d/pull/219)). Outside agents can no longer drive the app over MCP. The assistant that used your OpenAI or Anthropic API key is replaced by the studio agent.
- **The old backend** ([#220](https://github.com/AojdevStudio/materialize-3d/pull/220)): sign and part building, the printer connection, the print queue and auto-send, print history, MakerWorld downloads, OpenSCAD, and the old database. The updater no longer backs up a database before it installs.
- **Old data files and the STL slicer package** ([#221](https://github.com/AojdevStudio/materialize-3d/pull/221)).
- **The CAD helper and runtime** ([#222](https://github.com/AojdevStudio/materialize-3d/pull/222), [#223](https://github.com/AojdevStudio/materialize-3d/pull/223)). The app no longer ships the isolated CAD worker or its 864 MB of runtime images.

Fixes made after 0.2.2 to the old printer, MakerWorld, onboarding, and STL slicer code left with that code.

If you need any of these, choose **Later** and stay on 0.2.2.

## Your data

0.3.0 does not import, change, or delete 0.2.2's data. It stays on disk, and 0.3.0 does not show it.

| 0.2.2 data | Where it stays |
|---|---|
| Signs, parts, approvals, history, printers, and settings | `~/Library/Application Support/com.aojdevstudio.materialize3d/materialize.db` |
| Print queue | `~/Library/Application Support/materialize-3d/print_queue.json` |
| API keys and printer access codes | Keychain items named `com.materialize3d` |
| Files you exported with Save | Where you saved them |

- **Update now** in 0.2.2 backs up `materialize.db` and the print queue before it installs. The backup goes to `backups/0.2.2-to-0.3.0-<time>/` beside the database.
- 0.3.0 reads only its own sign-ins. Your 0.2.2 API key stays in the Keychain, but the agent does not use it. Sign in again from the start screen.
- If you reinstall 0.2.2 from its DMG, it opens that data again, because 0.3.0 leaves it as it was.

0.3.0 keeps its own data in new places:

- Chats in `~/Library/Application Support/com.aojdevstudio.materialize3d/state`.
- Project folders in `~/Documents/Materialize 3D`. macOS can ask to let the app use Documents. If it is not allowed, the app shows **Open Privacy settings** and **Try again** ([#201](https://github.com/AojdevStudio/materialize-3d/pull/201)).
- At each start, the app imports project folders from the studio's development builds once and keeps their files ([#201](https://github.com/AojdevStudio/materialize-3d/pull/201)). 0.2.2 never wrote these folders, so a 0.2.2 user has nothing to import.

## Requirements and limits

- Apple Silicon and macOS 26.0 or later. Intel Mac, Windows, and Linux release builds are not offered.
- A sign-in to one inference provider: Claude, ChatGPT, or OpenCode Go, by subscription or by API key. The provider's plan or API charges apply. The app is free.
- [uv](https://docs.astral.sh/uv/) and a Python it can run. After you install uv, run `uv python install`.
- [Bambu Studio 02.08.02.61](https://github.com/bambulab/BambuStudio/releases/tag/v02.08.02.61), installed separately. The app refuses other versions for slicing and does not bundle Bambu Studio.
- To print, a Bambu Lab P2S with a 0.4 mm nozzle.
- The app does not send jobs to a printer. Open the 3MF in Bambu Studio, check it, and print from there.
- Automated checks do not prove physical fit, strength, or a good print.

## Known issues

- Drawings and other agent pages that set their own look stay light in dark mode. The model view and guides follow the theme ([#233](https://github.com/AojdevStudio/materialize-3d/issues/233)).
- At a launch in dark mode, the native window shows light for about 0.2 seconds before the page paints black ([#236](https://github.com/AojdevStudio/materialize-3d/issues/236)).
- If the agent writes a guide step with no body, the guide page breaks and shows no step panel or buttons. The guide's step view also has smaller follow-ups, such as framing after a resize and keyboard focus ([#246](https://github.com/AojdevStudio/materialize-3d/issues/246)).

## Publication requirements

Follow the [release procedure](../releasing.md). Publishing 0.3.0 as **Latest** offers it to every installed 0.2.2 app at its next launch. Publish only after the required checks pass.

- Build a signed and notarized DMG and the update assets from a clean checkout of the `v0.3.0` tag, without `ALLOW_UNTAGGED`. The build checks the signatures, Gatekeeper, macOS 26.0 as the minimum, and the exact bundle file list.
- Run the [installed GUI checklist](../verify-on-mac.md) on that exact DMG: sign in, make and slice the calibration cube, open it in Bambu Studio 02.08.02.61 with the P2S 0.4 mm presets, and check persistence, interruption, and failure recovery.
- Attach the software acceptance record to the release. The record and the release body name the exact tagged source commit and the full DMG checksum. Keep those values out of tracked source.
- Download the published files and compare them with the build, as the release procedure's last step says.

## Installation

Download `Materialize-3D-0.3.0-macos-arm64.dmg` and its `.sha256` file from the [published release](https://github.com/AojdevStudio/materialize-3d/releases/tag/v0.3.0). Follow the [Mac install guide](../install-macos.md). Compare the downloaded DMG's full checksum with the checksum file, and stop on a mismatch.

```bash
shasum -a 256 ~/Downloads/Materialize-3D-0.3.0-macos-arm64.dmg
```

On 0.2.2, **Update now** installs 0.3.0 for you.
